# 部署指南:阿里云 e实例 + Nginx 反向代理

本文档描述把本项目部署到公网服务器的完整技术路线。

- **目标服务器**:阿里云 e 实例,2核 2G 内存,40G Entry 云盘,3M 固定带宽
- **技术路线**:Nginx 反向代理 + gunicorn(生产 WSGI 服务器)+ systemd 常驻 + MySQL 仅本机
- **访问方式**:无域名,`https://公网IP:端口` 直连,自签名 HTTPS 证书,仅个人/朋友圈子使用
- **不适用**:面向不特定公众开放的服务(那需要域名 + ICP 备案,或改用香港地域/私网组网,见文末"合规注意")

---

## 一、架构总览

```
朋友/你的浏览器
   │  HTTPS(自签证书, 9443 端口)        ← 阿里云安全组只放行这个端口 + SSH
   ▼
Nginx(反向代理, ~20MB 内存)
   │  proxy_pass → http://127.0.0.1:8000(仅本机回环,公网不可达)
   ▼
gunicorn × 1 worker × 8 线程(~150MB)
   │  import app:app,运行本项目的 Flask 代码
   ├── 定时更新线程(每 [schedule] 间隔,进程内)
   ▼
MySQL 8(仅监听 127.0.0.1,~400MB,专用低权限账号)
```

各组件职责:

| 组件 | 职责 |
| --- | --- |
| Nginx | 公网唯一入口;HTTPS 加解密;gzip 压缩;缓冲慢客户端;放大更新接口超时;传递真实 IP |
| gunicorn | 替代 Flask 开发服务器的生产级 WSGI 服务器;崩溃由 systemd 自动拉起 |
| systemd | 开机自启、进程守护、统一日志(journalctl) |
| MySQL | 只绑 127.0.0.1,公网与局域网均不可达;应用用专用账号,只给 SELECT/INSERT/UPDATE |

**为什么不用 `python3 app.py` 直接跑**:`app.run()` 是 Werkzeug 开发服务器,单进程线程模型、无进程守护、不做 gzip、未针对恶意请求打磨,仅适合本地调试。

## 二、资源测算(结论:2核2G 3M 够用)

**内存(共 2G)**:

| 项 | 常驻 |
| --- | --- |
| 系统底座(Ubuntu Server) | ~250MB |
| MySQL(调优后) | ~400MB |
| gunicorn 1 worker | ~150MB |
| Nginx | ~20MB |
| **合计** | **~850MB,余量 1G+** |

行情更新时 13 万条订单在内存聚合,峰值额外 ~130MB,依然宽裕。

**带宽(3M 仅限出方向,入方向免费且峰值更高)**:

- 出方向:主页 ~50KB + 目录 JSON 几十KB,375KB/s 对几个朋友的使用绰绰有余
- 入方向:每 2 小时拉 ESI 全量订单约 30-60MB,走免费入方向,不占 3M 配额

## 三、部署适配(已内置,环境变量开关)

以下适配**已包含在 0.7.0 代码中**,通过环境变量启停,不影响本地 `python3 app.py` 的现有用法(默认全部关闭,行为与之前完全一致):

| 环境变量 | 作用 | 在哪设置 |
| --- | --- | --- |
| `EVE_COST_BEHIND_PROXY=1` | 启用 ProxyFix,从 X-Forwarded-For 还原访客真实 IP。不开的话 Flask 看到的来源全是 127.0.0.1,登录失败锁定会把所有访客当成同一个人(一人输错 5 次密码全站锁 60 秒) | systemd 服务单元 |
| `EVE_COST_HTTPS=1` | 会话 Cookie 加 `Secure` 标记(仅经 HTTPS 传输) | systemd 服务单元 |
| `EVE_COST_DISABLE_AUTO_UPDATE=1` | 关闭进程内定时更新线程(仅当改用 systemd timer 单独跑更新脚本时才需要) | 一般不用设 |

定时更新线程已在**模块级**启动:`python3 app.py` 直跑与 gunicorn `import app` 方式均会生效(此前写在 `if __name__ == '__main__'` 里,gunicorn 下不会执行)。

**gunicorn 必须单 worker**(`--workers 1`):worker 数 >1 时每个 worker 都会执行模块级代码,定时线程会启动多份,且进程内 `_update_lock` 互相不可见,手动/定时更新会失去互斥。本应用是 I/O 型(查询毫秒级返回),1 worker × 8 线程足够。

`requirements.txt` 已包含 gunicorn,服务器上直接 `pip install -r requirements.txt` 即可。

## 五、数据库安装与数据迁移

```bash
sudo mysql_secure_installation   # 设 root 密码,移除匿名用户/测试库
```

调优(2G 内存):在 `/etc/mysql/mysql.conf.d/mysqld.cnf` 的 `[mysqld]` 段加:

```ini
bind-address = 127.0.0.1
innodb_buffer_pool_size = 128M
```

建库与专用账号(应用不使用 root,权限只给实际需要的):

```sql
CREATE DATABASE eve CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'eve'@'127.0.0.1' IDENTIFIED BY '独立强密码';
GRANT SELECT, INSERT, UPDATE ON eve.* TO 'eve'@'127.0.0.1';
FLUSH PRIVILEGES;
```

数据迁移(在本地机器执行导出,传到服务器导入):

```bash
# 本地:导出(应用只依赖 items / market_prices 两张表,均由 update_market.py 全量维护)
mysqldump -h127.0.0.1 -uroot -p eve > eve.sql
scp eve.sql 用户名@服务器IP:~

# 服务器:导入
mysql -uroot -p eve < ~/eve.sql
```

## 六、应用部署

```bash
cd /opt/eve-cost
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

`config.ini` 在服务器上单独手写(不进仓库,已被 .gitignore 忽略):

```ini
[database]
host = 127.0.0.1
port = 3306
user = eve
password = 上面建的独立强密码
database = eve

[security]
# 部署前重新生成,不要沿用本地值
admin_password = 新的强密码
secret_key = python3 -c "import secrets; print(secrets.token_hex(32))" 的输出

[schedule]
update_interval_seconds = 7200
```

systemd 服务 `/etc/systemd/system/eve-cost.service`(开机自启 + 崩溃自动拉起):

```ini
[Unit]
Description=EVE cost web app (gunicorn)
After=network.target mysql.service

[Service]
User=www-data
WorkingDirectory=/opt/eve-cost
Environment=EVE_COST_BEHIND_PROXY=1
Environment=EVE_COST_HTTPS=1
ExecStart=/opt/eve-cost/venv/bin/gunicorn --workers 1 --threads 8 \
    --bind 127.0.0.1:8000 --timeout 120 app:app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data:www-data /opt/eve-cost
sudo systemctl daemon-reload
sudo systemctl enable --now eve-cost
journalctl -u eve-cost -f        # 看日志,定时更新进度也在这里
```

## 七、Nginx 配置与自签 HTTPS

生成自签证书(无域名场景的标准做法,保护管理员密码不在公网明文传输):

```bash
sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -key /etc/nginx/ssl/eve.key -out /etc/nginx/ssl/eve.crt \
  -subj "/CN=服务器公网IP"
```

站点配置 `/etc/nginx/sites-available/eve-cost`:

```nginx
server {
    listen 9443 ssl;
    server_name _;

    ssl_certificate     /etc/nginx/ssl/eve.crt;
    ssl_certificate_key /etc/nginx/ssl/eve.key;

    gzip on;
    gzip_types text/html application/json;
    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 关键:默认 60s,手动更新最长 600s,不放大必 504
        proxy_read_timeout 660s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/eve-cost /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default     # 可选:移除默认站点
sudo nginx -t && sudo systemctl reload nginx
```

> 端口选择 9443 等非标准端口是刻意的:避开各层对 80/443 的 Web 拦截,也让"个人远程访问"的定性更清晰。改端口时注意三处一致:Nginx `listen`、阿里云安全组放行端口、告诉朋友的访问地址。

## 八、阿里云安全组

| 端口 | 动作 | 说明 |
| --- | --- | --- |
| 9443 | 放行 | 唯一的 Web 入口 |
| 22 | 放行(建议限定来源 IP) | SSH 运维 |
| 3306 | **拒绝** | MySQL 仅本机,绝不对外 |
| 8000 | 拒绝 | gunicorn 只绑 127.0.0.1,双保险 |

## 九、验收清单

1. 手机关掉 WiFi 用流量访问 `https://公网IP:9443`,点一次"高级 → 继续访问"(自签证书的正常提示),能查询物品
2. `https://公网IP:9443/admin` 登录管理员,点"立即更新行情数据库",确认不超时、日志正常显示
3. `journalctl -u eve-cost` 确认定时更新线程已启动并在跑
4. `ss -tlnp | grep -E '3306|8000'` 确认两个端口都只监听 127.0.0.1
5. 用 `nmap -p 3306 公网IP`(或在线端口扫描)确认 3306 从公网不可达

## 十、常见坑速查

| 症状 | 原因与解法 |
| --- | --- |
| 点更新后 504 Gateway Timeout | Nginx `proxy_read_timeout` 默认 60s,放大到 660s(见上文配置) |
| 一个访客输错密码,所有人都被锁 | 没配 ProxyFix,所有请求的 IP 都是 127.0.0.1;确认 `EVE_COST_BEHIND_PROXY=1` 已设置且 Nginx 传了 `X-Forwarded-For` |
| 定时更新在服务器上从不执行 | 线程还在 `if __name__ == '__main__'` 里;按第三节第 2 项挪到模块级 |
| gunicorn 日志报 worker timeout 被杀 | `--timeout` 默认 30s,已改为 120;仍不够就继续放大 |
| 登录后立刻被登出 | HTTPS 下没设 `SESSION_COOKIE_SECURE`,或环境变量 `EVE_COST_HTTPS` 配错 |
| 朋友打不开页面 | 三处端口不一致(Nginx listen / 安全组 / 访问地址),或安全组没放行 |

## 十一、日常运维

```bash
sudo systemctl restart eve-cost          # 重启应用(改代码/config.ini 后)
sudo systemctl reload nginx              # 重载 Nginx(改站点配置后)
journalctl -u eve-cost -f                # 实时日志(定时更新进度在)
journalctl -u eve-cost --since "2h ago"  # 最近 2 小时日志
sudo certrenew()                         # 自签证书 10 年有效期,一般无需续期
```

更新代码:本地改完 → `git push` → 服务器 `git pull` → `sudo systemctl restart eve-cost`。

## 十二、合规注意

本方案是"个人远程访问私有工具"的定位:非标准端口 + 自签证书 + 密码保护 + 安全组最小放行,不绑定域名故无 ICP 备案流程适用。若未来要**面向不特定玩家公开**(发军团群/论坛),性质变为面向公众的互联网信息服务,届时应二选一:改用阿里云香港地域(无备案制度),或购买域名走正规 ICP 备案(个人备案一般 1-3 周)。
