# 项目文件说明(详细版)

EVE Online(国服晨曦)制造成本估算工具。按配方清单估算材料总成本,行情直连网易 ESI 镜像。

## 整体数据流

```
网易 ESI 镜像 https://ali-esi.evepc.163.com/latest(datasource=serenity)
    │
    │  GET /markets/10000002/orders/?page=N   (整域订单,约 130 页 × 1000 条)
    ▼
update_market.py
    │  1. 扫描配方文件 + categories.json,收集跟踪物品(type_id/名称/分类)
    │  2. 并发拉取全部订单页(8 线程,失败重试)
    │  3. 只保留吉他 4-4 空间站订单(location_id=60003760),按 type_id 聚合
    │  4. upsert 写入 MySQL,不落任何中间文件
    ▼
MySQL(eve 库:items 表 + market_prices 表)
    │
    │  SELECT buy_max / sell_min ...
    ▼
Select.py
    │  按名称定位配方 JSON,P1 直接取价,P2~P4 递归计算合成成本
    ▼
app.py(Flask,:5000)
    ▼
templates/index.html(浏览器)
```

## 一、根目录代码文件

### `app.py` — Flask Web 服务

项目入口,`python app.py` 后访问 http://localhost:5000。以 `debug=True, host=0.0.0.0` 运行(局域网可访问,改代码自动重启)。

路由一览:

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 返回 `templates/index.html` 页面 |
| `/query` | POST | 单个成本查询。入参 `{"name": "氧", "quantity": 8}`,调用 `Select.query_by_name`,返回 `{success, data}` 或 `{success: False, error}` |
| `/query_batch` | POST | 批量查询。入参 `{"items": [{name, quantity}, ...]}`,返回每项明细外加 `grand_total_buy` / `grand_total_sell` 汇总 |
| `/catalog` | GET | 物品目录。调用 `Select.get_catalog`,返回全部物品的 id/name/buy_max/sell_min/update_time/tier |
| `/update_database` | POST | 一键更新行情。用 `subprocess` 调用 `update_market.py`(超时 600 秒),从 stdout 用正则 `导入完成,共更新 (\d+) 条记录` 解析更新条数返回给前端 |

依赖:`Select.py` 的 `query_by_name` 和 `get_catalog`。

### `Select.py` — 成本计算核心

被 `app.py` 导入,也可命令行独立使用。只读数据库,不写。

关键函数:

| 函数 | 说明 |
| --- | --- |
| `find_json_file(name)` | 在全部配方目录递归查找 `{name}.json`;命中多个时优先非 `old` 目录的版本并打印警告 |
| `_query_price_map(ids)` | 批量查 `market_prices` 表,返回 `{type_id: (buy_max, sell_min)}`,固定 `region_id=10000002` |
| `_query_p1(data, quantity)` | P1 基础材料:直接取数据库市场价 × 数量 |
| `_query_crafted(data, quantity, tier)` | P2~P4 及标准矿石通用递归:`单个成本 = Σ(材料成本 × 数量) / outputCount`;材料为 P1 时查库,为合成物时继续递归;同时查出成品自身的市场价(`market_buy`/`market_sell`)供前端对比"自制 vs 直接买" |
| `query_by_name(name, quantity)` | 对外主接口。定位配方文件 → 有 `recipe` 走 `_query_crafted`,否则走 `_query_p1` |
| `get_catalog()` | 联表查询 `items LEFT JOIN market_prices`,返回目录列表;`tier` 字段直接取 `items.category`(入库时已写好),前端按它渲染分类侧栏 |

成本口径:

- `buy_max`:市场上最高的收购挂单(玩家即时卖出能拿到的钱)
- `sell_min`:市场上最低的出售挂单(玩家即时买入要付的钱)
- 总成本同时给出两种口径,前端分别展示

### `update_market.py` — 行情更新流水线

直连 ESI,替代旧的"ceve-market → JSON → CSV → MySQL"三层流程。

执行步骤:

1. **收集跟踪物品** `collect_tracked_items()`
   - 扫描 8 个配方目录(跳过 `old/` 子目录和解析失败的文件),收集每个配方的 `id` 和 `recipe.inputs[].materialId`
   - 追加 `EXTRA_TYPE_IDS` 中手工登记的物品(氧/氢/氦/氮燃料块,它们不在任何配方里但有市场价)
   - 打分类标签:行星产物按目录记 `P1~P4`,其余查 `categories.json`,都不在记 `其他`
2. **整域拉取订单** `fetch_region_orders()`
   - `GET /markets/10000002/orders/`(伏尔戈星域),先取第 1 页从响应头 `X-Pages` 得知总页数,再 8 线程并发拉剩余页
   - 每次请求带 `datasource=serenity`;失败按 2/4/6/8 秒递增重试,最多 4 次
3. **吉他 4-4 聚合** `aggregate_jita44(orders)`
   - 只保留 `location_id == 60003760`(吉他 IV - 卫星 4 - 加达里海军组装车间)的订单
   - 按 `type_id` 聚合:买单取价格 max/min、求和 `volume_remain`;卖单同理
4. **入库** `sync_to_db(tracked, stats)`
   - `items`:`INSERT ... ON DUPLICATE KEY UPDATE`(新物品自动插入,已有物品更新名称/分类)
   - `market_prices`:同样 upsert,主键 `(type_id, region_id)`;跟踪清单里当期无订单的物品价格置 0,避免展示过期价格
   - 每 100 条一批 `executemany`,全部成功后一次 commit,失败 rollback

顶部可调配置:`ESI`(镜像地址)、`DATASOURCE`、`REGION_ID`、`JITA_44`、`MAX_WORKERS`(并发数)、`EXTRA_TYPE_IDS`(补充物品)。

### `db_config.py` — 数据库配置加载器

唯一函数 `load_db_config()`:读取与脚本同目录的 `config.ini` 的 `[database]` 段,返回 `pymysql.connect()` 可用的参数字典(host/port/user/password/database,固定 `utf8mb4`、关 autocommit)。`config.ini` 不存在时抛出带指引的 `FileNotFoundError`。

被 `update_market.py` 和 `Select.py` 共同引用,密码不落在任何代码文件里。

### `config.example.ini` / `config.ini`

数据库配置模板与真实配置。用法:`cp config.example.ini config.ini` 后填写密码。`config.ini` 已加入 `.gitignore`,不会进入仓库。

### `schema.sql` — 建库建表脚本

`mysql -u root -p < schema.sql` 一键初始化:

```sql
items(                                  -- 物品静态信息,几乎不变
    type_id  INT PRIMARY KEY,
    name     VARCHAR(64) NOT NULL,
    category VARCHAR(32) NOT NULL DEFAULT '其他'   -- P1~P4 / 矿物 / 气云 ... / 其他
)

market_prices(                          -- 行情快照,每次更新整体覆盖
    type_id     INT NOT NULL,
    region_id   INT NOT NULL,           -- 固定 10000002,保留做多市场扩展
    buy_max     DOUBLE,  buy_min  DOUBLE,
    sell_max    DOUBLE,  sell_min DOUBLE,
    buy_volume  BIGINT,  sell_volume BIGINT,
    updated_at  DATETIME,               -- 注意是完整日期时间(旧 test 表只有 time)
    PRIMARY KEY (type_id, region_id)
)
```

### `categories.json` — 自定义分类配置

格式 `{"分类名": ["物品名", ...]}`,现有:矿物、卫星原料、气云、燃料、挖坟材料。在 `update_market.py` 入库时写入 `items.category`;行星产物的 P1~P4 分类优先级更高,不会被此文件覆盖。

## 二、templates/(前端页面)

### `index.html` — 当前页面(约 1200 行,单文件含 CSS/JS)

页面区块:

- **待查询物品列表**:物品名 + 数量,可增删行;支持从游戏内批量粘贴(自动解析千分位数量,如 `52,100`)
- **成本明细结果区**:表格展示每层材料的单件需要、总需要、单价、小计;合成品标注 `[P2 合成 | 单次产出 N 个]` 等层级标签;成品附带市场价对比
- **左侧物品目录**:按分类分组(行星商品 P1~P4 + categories.json 自定义分类 + 其他),支持搜索过滤,点击物品弹窗显示 buy_max/sell_min/更新时间
- **更新数据库按钮**:点击置灰显示"更新中",POST `/update_database`,完成后显示"数据库更新成功(共更新 N 条记录)"并自动刷新目录

前端约定的数据字段(后端必须保持):物品的 `id/name/buy_max/sell_min/update_time/tier`,查询结果的 `materials/total_buy/total_sell/output_count/market_buy/market_sell` 等。

## 三、配方数据目录(业务配置,Git 管理)

配方 JSON 是成本计算的输入,分两类格式:

**基础材料(无 recipe)** — 直接取数据库市场价:

```json
{ "id": 2393, "name": "细菌", "tier": "P1" }
```

**合成物品(有 recipe)** — 成本递归计算:

```json
{
  "id": 3689, "name": "机械元件", "tier": "P2",
  "recipe": {
    "outputCount": 5,
    "inputs": [
      { "materialId": 2398, "materialname": "反应金属", "count": 40 },
      { "materialId": 2399, "materialname": "稀有金属", "count": 40 }
    ]
  }
}
```

即:5 个机械元件 = 40 反应金属 + 40 稀有金属,单件成本 = 材料总价 / 5。

| 目录 | 内容 | 计价方式 |
| --- | --- | --- |
| `Planetary_Commodities/P1` | 行星产物 P1(细菌、氧等 15 种) | 市场价 |
| `Planetary_Commodities/P2` | P2(机械元件、冷却剂等 24 种) | 两种 P1 合成 |
| `Planetary_Commodities/P3` | P3(机器人技术、制导系统等 21 种) | P2 合成 |
| `Planetary_Commodities/P4` | P4(有机砂浆喷注器等 8 种) | P3/P2 合成 |
| `Ore/` | 基础矿物(三钛合金、类晶体胶矿等 8 种) | 市场价 |
| `Ore/StandardOres/` | 标准矿石(凡晶石等,含 2~4 级浓缩变体) | **无直接市场价**(`id` 为空):recipe 表示"100 单位矿石提炼出的产物",按提炼产物的市场价折算单矿石价值 |
| `MoonMaterials/` | 卫星原料(钒、钨等 20 种) | 市场价 |
| `Gas/` | 气云(富勒体、丝胶溶质等 25 种) | 市场价 |
| `Commodities/` | 挖坟材料(分子冷凝器等 11 种) | 市场价 |

特殊文件(均不参与计算):

- `Planetary_Commodities/*/old/`:旧格式备份(`{"TypeID": ..., "P2_list": ...}` 结构),`find_json_file` 和 `update_market.py` 都跳过 `old` 目录
- `Planetary_Commodities/P3/test.json`、`P2/old/test.json`:无效/模板文件,JSON 解析失败被忽略
