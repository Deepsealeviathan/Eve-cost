# 项目文件说明(详细版)

EVE Online(国服晨曦)制造成本估算工具。按配方清单估算材料总成本,行情直连网易 ESI 镜像。

## 整体数据流

```
网易 ESI 镜像 https://ali-esi.evepc.163.com/latest(datasource=serenity)
    │
    │  GET /markets/{region}/orders/?page=N   (整域订单,约 130 页 × 1000 条;region 取自 config.ini [market])
    │  GET /markets/{region}/history/?type_id=X (0.8.0 历史日线,404=无成交)
    │  GET /markets/prices/                    (调整价 adjusted_price,制造安装费 EIV)
    ▼
update_market.py
    │  1. 扫描配方文件 + categories.json,收集跟踪物品(type_id/名称/分类)
    │     并并入 reprocessing.json 的化矿物品(只跟踪价格,不写入主目录)
    │  2. 并发拉取全部订单页(8 线程,失败重试)
    │  3. 只保留吉他 4-4 空间站订单(location_id=60003760),按 type_id 聚合
    │  4. upsert 写入 MySQL,不落任何中间文件
    │  5. 调整价入库(只保留配方跟踪物品,供官方 EIV 公式计算安装费)
    │  6. 历史行情增量入库(只拉配方物品,化矿垃圾不拉历史)
    │  7. 利润快照预计算(全部可制造物品的单件成本 vs 市场价,写快照表)
    │  8. 清理 price_history 中 365 天前的旧日线
    ▼
MySQL(eve 库:items / market_prices / adjusted_prices / price_history / profit_snapshot 五张表)
    │  SELECT buy_max / sell_min / adjusted_price ...
    ▼
Select.py                        reprocessing.py
    │  制造成本递归计算              │  化矿清单 + 行情 → 55% 产出/利润
    ▼                              ▼
app.py(Flask,:38000)
    ▼
templates/index.html · components.html · bom.html · profit.html · reprocess.html · admin_health.html(浏览器)

触发方式(app.py):后台线程定时执行(启动 30s 后首次,此后每
[schedule].update_interval_seconds 一次,默认 2h)+ 管理员手动触发(/update_database),
两者经 _update_lock 互斥,同一时间只跑一个任务。历史行情与利润快照为附加步骤,失败只记日志、不影响价格主流程。
```

## 一、根目录代码文件

### `app.py` — Flask Web 服务

项目入口,`python app.py` 后访问 http://localhost:38000(端口可用 `EVE_COST_PORT` 覆盖)。以 `host=0.0.0.0` 运行(局域网可访问)。**debug 默认关闭**(调试模式会向局域网暴露 Werkzeug 调试器,可执行任意代码,有安全风险);本地开发需要改代码自动重启时用 `EVE_COST_DEBUG=1 python app.py` 显式开启。

部署适配(0.7.0,环境变量开关,默认全部关闭):`EVE_COST_BEHIND_PROXY=1` 启用 ProxyFix(反代下从 X-Forwarded-For 还原访客真实 IP,登录锁定才按真实 IP 生效);`EVE_COST_HTTPS=1` 会话 Cookie 加 Secure 标记;`EVE_COST_DISABLE_AUTO_UPDATE=1` 关闭进程内定时更新线程。定时更新线程为**模块级启动**,gunicorn `import app` 方式同样生效(须单 worker)。详见 `Doc/部署指南.md`。

路由一览:

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 返回 `templates/index.html` 页面 |
| `/query` | POST | 单个成本查询。入参 `{"name": "氧", "quantity": 8}`,调用 `Select.query_by_name`,返回 `{success, data}` 或 `{success: False, error}` |
| `/query_batch` | POST | 批量查询。入参 `{"items": [{name, quantity}, ...]}`,返回每项明细外加 `grand_total_buy` / `grand_total_sell` 汇总 |
| `/catalog` | GET | 物品目录。调用 `Select.get_catalog`(30 秒进程内缓存),返回全部物品的 id/name/buy_max/buy_min/sell_max/sell_min/buy_volume/sell_volume/update_time/tier |
| `/update_database` | POST | **仅管理员**(游客 403):一键更新行情。用 `subprocess` 调用 `update_market.py`(超时 600 秒),从 stdout 用正则 `导入完成,共更新 (\d+) 条记录` 解析更新条数返回给前端;与定时更新共用 `_update_lock` 互斥 |
| `/components` | GET | 组件制造计算器页面。左侧目录选择旗舰基础/旗舰高级/T2 制造组件,右侧显示制造材料、`−/+` 调整数量,并可选择建筑加成(效率插件 + 堡垒 + 星系安等 + 蓝图 ME)计算材料减免;新增星系成本系数输入,按官方 EIV 公式估算制造安装费(建筑费用减免 0/3/4/5%,SCC 固定 4%,按设施税 0%、非 Alpha 克隆计算) |
| `/bom` | GET | 制造清单汇总器页面。粘贴整份购物单(如旗舰全套组件),递归展开到最终原材料 |
| `/reprocess` | GET | 垃圾回收化矿页面。全部 T1 衍生装备(衍生 1~4 级)与 T1 弹药,按最高 55% 化矿率计算每份产物、利润和批量收益 |
| `/api/reprocess` | GET | 化矿数据接口。调用 `reprocessing.get_catalog`,返回物品、化矿配方、材料行情与物品行情;计算在浏览器端按选定化矿率完成 |
| `/recipes` | GET | 配方索引。调用 `Select.get_recipes`,返回全部配方的 name/id/tier/outputCount/inputs 轻量列表,供 BOM 页前端递归展开 |
| `/admin` | GET | 管理控制台页面(`templates/admin.html`),与主页面分离;主页面不展示任何管理员入口 |
| `/admin/status` | GET | 返回 `{admin: true/false}`,管理控制台据此切换登录视图/管理视图 |
| `/admin/login` | POST | 入参 `{"password": ...}`,校验 `config.ini [security].admin_password`;成功设置签名会话 Cookie(密钥 `[security].secret_key`);密码错误返回 401,任意 60 秒窗口内同 IP 失败 5 次锁定 60 秒(429) |
| `/admin/logout` | POST | 清除管理员会话 |
| `/admin/health` | GET | 数据自检页(`templates/admin_health.html`):行情新鲜度、无报价物品、配方/调整价/历史行情/利润快照覆盖度,游客也可访问(只读统计) |
| `/api/health` | GET | 自检数据接口。调用 `Select.get_health`,返回上述统计的 JSON |

`_auto_update_loop`(后台守护线程):启动 30 秒后经 `_update_lock` 执行首次 `update_market.main()`,此后每 `load_schedule_config()['update_interval_seconds']`(默认 7200)秒一次;异常仅打印日志,不打断循环。每次更新完成后调用 `Select.invalidate_catalog_cache()` 让目录立即刷新。查询接口(`/query` 等)全程游客可用。

会话与编码:管理员登录成功后 `session.permanent = True`,`PERMANENT_SESSION_LIFETIME` 为 30 分钟闲置过期(每次请求顺延);`app.json.ensure_ascii = False` 让接口直接返回可读中文,便于调试。服务端日志统一用 `logging`(`%(asctime)s %(levelname)s %(name)s: %(message)s`),接口异常经 `_api_error()` 记录完整堆栈、前端只看到友好提示。

错误处理约定(0.7.0):查询类接口(`/query`、`/query_batch`、`/catalog`、`/recipes`)的意外异常统一经 `_api_error()` 返回友好提示(如"查询失败,请稍后重试"),原始报错文本只打印到服务端日志——避免把网络层报错(如 WSL 端口转发抖动产生的 `[Errno 32] Broken pipe`)直接弹给用户;入参校验(数量非法、JSON 格式错误)返回明确中文提示。

依赖:`Select.py` 的 `query_by_name`、`get_catalog` 和 `get_recipes`。

### `Select.py` — 成本计算核心

被 `app.py` 导入,也可命令行独立使用。只读数据库,不写。模块顶部的 `REGION_ID` 由 `db_config.get_region_id()` 读取(默认 10000002),与行情更新、化矿页共用同一星域。

关键函数:

| 函数 | 说明 |
| --- | --- |
| `normalize_name(name)` | 物品名归一化:全角括号/乘号转半角、去掉所有空白,`白釉冰(4级)` 与 `白釉冰（4级）` 同键 |
| `find_json_file(name)` | 先按文件名精确查找,未命中再用归一化名匹配(全角/半角括号、空格差异);索引带 10 秒 TTL,新增配方文件无需重启;同名文件取首个并记日志 |
| `get_catalog(use_cache=True)` | 联表查询 `items LEFT JOIN market_prices`,返回目录列表(id/name/买卖价/挂单量/update_time/tier);结果 30 秒进程内缓存,`invalidate_catalog_cache()` 可立即失效 |
| `get_health()` | 数据自检:行情最后更新时间、有价/无价物品与无报价清单、分类分布、配方/材料统计、调整价覆盖(缺调整价的材料 ID)、历史日线范围、利润快照时间;表不存在时按 0 返回 |
| `_query_price_map(ids, ctx)` | 批量查 `market_prices` 表,返回 `{type_id: (buy_max, sell_min)}`,星域取 `db_config.get_region_id()`;结果缓存进 ctx,避免递归重复查询 |
| `_query_adjusted_prices(ids, ctx)` | 读取 `adjusted_prices` 表(ESI `adjusted_price`);首次调用把整表加载进 ctx,后续零查询。表不存在时返回空映射,制造安装费降级为 0 并提示 |
| `_query_p1(data, quantity, ctx)` | 基础材料(矿物/卫星原料/气云/挖坟材料等无配方物品):直接取数据库市场价 × 数量 |
| `_query_crafted(data, quantity, tier, ctx)` | 有配方物品(行星 P2~P4、反应物、组件、标准矿石、冰矿、燃料块)通用递归:`单个成本 = Σ(材料成本 × 数量) / outputCount`;材料递归计算,最终落实到基础材料价格;同时查出成品自身的市场价(`market_buy`/`market_sell`)供前端对比"自制 vs 直接买";另返回 `eiv_per_run`(ME0 单轮材料量 × adjusted_price)与 `eiv_complete`(是否缺调整价),供组件页按官方公式算安装费 |
| `query_by_name(name, quantity)` | 对外主接口。定位配方文件 → 有 `recipe` 走 `_query_crafted`,否则走 `_query_p1`;顶层调用自动创建 `_QueryContext`(共享一条数据库连接 + 价格缓存 + 调整价缓存),递归结束后关闭 |

数据库连接自愈(0.7.0):MySQL 位于 Windows 侧、经 WSL 端口转发访问时,高频新建连接偶发被转发层中断(原始报错 `[Errno 32] Broken pipe`)。`get_conn()`/`get_catalog()`/`_query_price_map()` 遇连接类错误(`pymysql.Error`/`OSError`)会丢弃旧连接、自动重试一次,瞬时抖动对用户完全无感;重试仍失败才降级(价格记 0 并打印日志)。
| `get_catalog()` | 联表查询 `items LEFT JOIN market_prices`,返回目录列表;`tier` 字段直接取 `items.category`(入库时已写好),前端按它渲染分类侧栏 |
| `get_recipes()` | 汇总全部配方 JSON 为轻量索引(name/id/tier/outputCount/inputs),同名物品保留先出现的(与 `find_json_file` 行为一致);供 `/recipes` 接口与 BOM 页使用 |
| `compute_profit_rows()` | 0.8.0:遍历全部可制造物品,共享一个 `_QueryContext` 算出单件成本(即时采购/挂单收购两种口径)与市场价,供流水线写利润快照;材料树含缺价材料或成本为 0 时标 `complete=0` |
| `get_profit_snapshot()` | 0.8.0:读取 `profit_snapshot` 快照(利润排行页数据源);表不存在时返回空结果而非报错,前端提示"快照尚未生成" |
| `get_price_history(type_id)` | 0.8.0:读取单物品历史日线(近 90 天),供 `/api/history` 趋势图;表不存在返回空列表 |

成本口径:

- `buy_max`:市场上最高的收购挂单(玩家即时卖出能拿到的钱)
- `sell_min`:市场上最低的出售挂单(玩家即时买入要付的钱)
- 总成本同时给出两种口径,前端分别展示

### `update_market.py` — 行情更新流水线

直连 ESI,替代旧的"ceve-market → JSON → CSV → MySQL"三层流程。

执行步骤:

1. **收集跟踪物品** `collect_tracked_items()`
   - 扫描 19 个配方目录(跳过解析失败的文件),收集每个配方的 `id` 和 `recipe.inputs[].materialId`
   - 跟踪清单完全由配方文件决定;0.9.0 前用于补充「无配方但有市价物品」的 `EXTRA_TYPE_IDS` 已删除(燃料块已有自带配方)
   - 打分类标签:行星产物按目录记 `P1~P4`,其余查 `categories.json`,都不在记 `其他`
   - 并入 `reprocessing.json` 的物品与化矿产物 ID:这些只跟踪 `market_prices`,不进入 `items` 主目录、不拉历史行情
2. **整域拉取订单** `fetch_region_orders()`
   - `GET /markets/10000002/orders/`(伏尔戈星域),先取第 1 页从响应头 `X-Pages` 得知总页数,再 8 线程并发拉剩余页
   - 每次请求带 `datasource=serenity`;失败按 2/4/6/8 秒递增重试,最多 4 次
3. **吉他 4-4 聚合** `aggregate_jita44(orders)`
   - 只保留 `location_id == 60003760`(吉他 IV - 卫星 4 - 加达里海军组装车间)的订单
   - 按 `type_id` 聚合:买单取价格 max/min、求和 `volume_remain`;卖单同理
4. **入库** `sync_to_db(tracked, stats, catalog_ids)`
   - `items`:`INSERT ... ON DUPLICATE KEY UPDATE`(只写配方物品;化矿物品被 `catalog_ids` 排除,避免主目录被数百个垃圾装备淹没)
   - `market_prices`:同样 upsert,主键 `(type_id, region_id)`;配方物品与化矿物品都写,跟踪清单里当期无订单的物品价格置 0,避免展示过期价格
   - 每 100 条一批 `executemany`,全部成功后一次 commit,失败 rollback
5. **调整价入库** `fetch_adjusted_prices()` + `sync_adjusted_prices()`
   - `GET /markets/prices/` 拉取全量 `adjusted_price`,只保留配方跟踪清单内的 type_id,upsert 进 `adjusted_prices`
   - 这是组件计算器页按官方 EIV 公式估算制造安装费的数据源,与吉他市场价不是同一套数据
6. **历史行情增量入库** `fetch_price_history()` + `sync_price_history()`(0.8.0)
   - 逐物品 `GET /markets/10000002/history/?type_id=X`(8 线程并发);从未有过成交的物品 ESI 返回 404,直接跳过不重试
   - 只对配方物品拉取;数百个化矿垃圾不拉历史,避免每轮更新多出上千次请求
   - 只写比库内该物品最新日期更新的行(绝大多数周期每物品 0~1 条),拉取窗口近 90 天(`HISTORY_DAYS`)
   - 每次顺带 `DELETE FROM price_history WHERE date < CURDATE() - INTERVAL 365 DAY`,库里最多保留一年(`HISTORY_KEEP_DAYS`)
7. **利润快照预计算** `snapshot_profit()`(0.8.0)
   - 调 `Select.compute_profit_rows()` 算全部可制造物品的单件成本与市场价,upsert 进 `profit_snapshot`,利润排行页直接读快照、零计算开销

5、6、7 三步失败只打印日志,不影响价格主流程。

顶部可调配置:`ESI`(镜像地址)、`DATASOURCE`、`REGION_ID`(来自 `config.ini [market]`)、`JITA_44`、`MAX_WORKERS`(并发数)、`HISTORY_DAYS`(拉取窗口)、`HISTORY_KEEP_DAYS`(库内保留天数)。

### `reprocessing.py` — 垃圾回收化矿

`/reprocess` 页面与 `/api/reprocess` 的数据层,只读数据库和本地清单。

| 函数 | 说明 |
| --- | --- |
| `load_data()` | 按 mtime 缓存读取 `reprocessing.json`,数据文件更新后自动重载 |
| `price_ids()` | 返回页面需要的报价 ID:化矿物品本身 + 全部化矿产物;`update_market.py` 用它扩展价格跟踪清单 |
| `get_catalog()` | 批量查询 `market_prices`(每 500 个 ID 一批),返回物品、材料行情与行情更新时间;缺失报价按 0 处理 |

化矿计算在前端完成:每份产出 = `floor(每份基础材料量 × 份数 × 化矿率)`;份数 = `floor(物品数量 ÷ 每份数量)`,不足一份的余数不参与化矿。页面默认 55%,输入上限也是 55%。

### `reprocessing.json` — 化矿清单

由 `build_reprocessing_data.py` 生成,约 220KB:

```json
{
  "version": 1,
  "max_rate": 0.55,
  "material_names": { "34": "三钛合金", "35": "类晶体胶矿" },
  "items": [
    {
      "id": 178, "name": "碳铅弹 S", "group": "射弹弹药",
      "kind": "ammo", "meta_level": 0, "portion_size": 100,
      "materials": [{ "id": 34, "quantity": 27 }, { "id": 35, "quantity": 21 }]
    }
  ]
}
```

筛选口径:

- **装备**:ESI 分类「装备」中 `metaLevel` 在 1~4 的物品;`meta_level` 即衍生等级
- **弹药**:ESI 分类「弹药」中的 Tech I 弹药,包括 `metaGroupID = 1` 的常规弹药,以及炸弹/脚本/电容装料等 SDE 未标 `metaGroupID` 的基础弹药;排除 T2、势力、死亡空间等衍生弹药
- 只保留 SDE `typeMaterials` 中有化矿产物的物品,并剔除晨曦 ESI 不存在的条目
- 当前共 889 个物品(装备 621、弹药 268),化矿产物 28 种

### `build_reprocessing_data.py` — 化矿清单生成器

```bash
python build_reprocessing_data.py                  # 自动下载最新官方 SDE
python build_reprocessing_data.py --sde sde.zip    # 复用已下载的 SDE
```

下载官方 SDE JSONL 压缩包,读取 `types.jsonl` / `groups.jsonl` / `typeMaterials.jsonl` 筛出候选,再并发调用网易 ESI 的 `/universe/types/{id}` 与 `/universe/groups/{id}` 取晨曦中文名与分组,最后写入 `reprocessing.json`。运行期服务不依赖 SDE。

### `build_ice_data.py` — 冰矿配方生成器

```bash
python build_ice_data.py                  # 只重写仓库已有的 12 种冰矿(默认,结果稳定)
python build_ice_data.py --all            # 生成 SDE 中全部可化矿冰矿(含高密度等旧版变体)
python build_ice_data.py --sde sde.zip    # 复用已下载的 SDE
```

从 SDE 分组 465「冰矿」取 `typeMaterials`(按 `portionSize` 归一,冰矿为 1),产物固定为分组 423 的 7 种冰矿产物;名称优先取网易 ESI 晨曦中文名,缺失回退 SDE 中文名。写入后自动回读比对材料数量,输出「自检:全部与 SDE 一致」。默认模式与仓库现有 12 个文件逐字节一致,可用于校验/修复手工改动。

### `db_config.py` — 数据库配置加载器

四个加载器共用 `_load_parser()`(读取与脚本同目录的 `config.ini`):

| 函数 | 读取段 | 说明 |
| --- | --- | --- |
| `load_db_config()` | `[database]` | 返回 `pymysql.connect()` 可用的参数字典(host/port/user/password/database,固定 `utf8mb4`、关 autocommit) |

`mysql -u root -p < schema.sql` 一键初始化:

```sql
items(                                  -- 物品静态信息,几乎不变
    type_id  INT PRIMARY KEY,
    name     VARCHAR(64) NOT NULL,
    category VARCHAR(32) NOT NULL DEFAULT '其他'   -- P1~P4 / 矿物 / 气云 ... / 其他

market_prices(                          -- 行情快照,每次更新整体覆盖

    region_id   INT NOT NULL,           -- 固定 10000002,保留做多市场扩展
    buy_max     DOUBLE,  buy_min  DOUBLE,
    sell_max    DOUBLE,  sell_min DOUBLE,
    buy_volume  BIGINT,  sell_volume BIGINT,
    updated_at  DATETIME,               -- 注意是完整日期时间(旧 test 表只有 time)
    PRIMARY KEY (type_id, region_id)
)

profit_snapshot(                        -- 0.8.0 利润快照,每次行情更新后重算
    type_id            INT PRIMARY KEY,
    name               VARCHAR(64) NOT NULL,
    category           VARCHAR(32) NOT NULL DEFAULT '其他',
    unit_cost_instant  DOUBLE,          -- 单件成本:材料按最低卖单即时采购
    unit_cost_buyorder DOUBLE,          -- 单件成本:材料按最高买单挂单收购

    market_buy_max     DOUBLE,          -- 最高买单(即时卖出到手价)
    complete           TINYINT NOT NULL DEFAULT 1,  -- 0=配方含无价材料
    updated_at         DATETIME
)

price_history(                          -- 0.8.0 历史日线,趋势图使用,增量写入(自动清理 365 天前数据)
    type_id     INT NOT NULL,

)

adjusted_prices(                        -- ESI 调整价,制造安装费(EIV)计算用
    type_id        INT PRIMARY KEY,
    adjusted_price DOUBLE,              -- 官方 EIV 取数:ME0 材料量 × adjusted_price
    average_price  DOUBLE,

)
```

- **数量控制**:`− / +` 按钮或直接输入,实时重算
- **建筑加成**:先选建筑(NPC 站无减免 / 莱塔卢·中型 / 阿兹贝尔·大型 / 索迪约·超大型;工程综合体材料减免 1%,安装费减免分别为 3% / 4% / 5%),再勾选该建筑实际安装的改装件(**可多选,同一建筑最多 3 个;同类不叠加,取最高**;规格须与建筑匹配)、星系安全等级(影响改装件系数:高安 ×1.0 / 低安 ×1.9 / 00 与虫洞 ×2.1,仅放大改装件、不放大结构 1%,经晨曦 ESI dogma 属性核实)、蓝图 ME 等级(每级 −1%,研究 10 级共 −10%)

## 三、配方数据目录(业务配置,Git 管理)

配方 JSON 是成本计算的输入,分两类格式:

**基础材料(无 recipe)** — 直接取数据库市场价:

```json
{ "id": 2393, "name": "细菌", "tier": "P1" }
```

**合成物品(有 recipe)** — 成本递归计算:

```json
{
  "id": 3689, "name": "机械元件", "tier": "P2",
  "recipe": {
    "outputCount": 5,
    "inputs": [
      { "materialId": 2398, "materialname": "反应金属", "count": 40 },
      { "materialId": 2399, "materialname": "稀有金属", "count": 40 }
    ]
  }
}
```

即:5 个机械元件 = 40 反应金属 + 40 稀有金属,单件成本 = 材料总价 / 5。

| 目录 | 内容 | 计价方式 |
| --- | --- | --- |
| `Planetary_Commodities/P1` | 行星产物 P1(细菌、氧等 15 种) | 市场价 |
| `Planetary_Commodities/P2` | P2(机械元件、冷却剂等 24 种) | 两种 P1 合成 |
| `Planetary_Commodities/P3` | P3(机器人技术、制导系统等 21 种) | P2 合成 |
